DE WERKBRANCH IS: main — en die naam verandert nooit meer.

Zelfde reden als bij Run A en Run B: Claude Code geeft elke sessie een eigen willekeurige
branchnaam, dus een sessienaam in deze tekst loopt gegarandeerd uit de pas. Stap 0 hieronder

"Pak de nieuwste branch" is expliciet NIET genoeg — op 10 aug 2026 bevatten twee takken allebei
werk dat de ander niet had, dus kiezen betekende hoe dan ook iets weggooien. Samenvoegen is de
opdracht.

DRIE RUNS OP DEZELFDE BRANCH. Dat is bewust; run: "A"/"B"/"C" in het schema houdt ze uit
elkaar. Plan ze niet op hetzelfde tijdstip — ze pushen alle drie naar main, en een botsing
kost een merge. Loopt een push toch stuk omdat main is opgeschoven, fetch dan opnieuw, merge
volgens de conflictregels van stap 0, en push nog een keer. Forceer nooit: aan de andere kant
hangt een echte run met echte picks.

WAT DEZE RUN ANDERS MAAKT, EN WAT JE DAARVAN MOET VERWACHTEN.

Run C kijkt alleen naar landenteams. Het clubmodel werkt daar niet: een oefeninterland heeft
geen stand en dus geen competitiegemiddelde om twee ploegen op te normaliseren. Daarvoor in de
plaats staat scripts/national.py — een aanval- en verdedigingsrating voor elk landenteam op één
gezamenlijke schaal, gefit op 6784 werkelijke interlanduitslagen, uit-steekproef gemeten op
Brier 0,4796 tegen 0,6667 voor blind gokken. prompts/run-c.md legt uit hoe je hem gebruikt; de
rest van de pijplijn draait er ongewijzigd op.

Twee dingen die je daarvan moet verwachten. Het datatier blijft op LIGHT staan — er is maar één
methode en geen xG, dus de drempel is 16,0 procentpunt en er komt weinig doorheen. En op de
meeste dagen van het jaar speelt er helemaal geen interland. Allebei is dat de eerlijke uitkomst
van wat er gemeten is, geen defect. Rapporteer de dekking en zeg met zoveel woorden wat er niet
kon, in plaats van een lege pagina af te leveren.

Draai `python3 scripts/national.py build` en daarna `fit` aan het EIND van elk interlandvenster,
niet elke dag: het corpus verandert alleen als er interlands gespeeld zijn. Commit de uitkomst
mee — data/national-matches.jsonl en data/national-fit.json zijn metingen, geen cache.

Werk in de repo /home/user/football. De canonieke branch is main, en je hebt hierbij
expliciet toestemming om daarheen te pushen — ook als deze sessie op een andere branch is
gezet. Zonder die toestemming weigert een sessie dat.

0. EERST DE BRANCHES OP ORDE. Doe dit vóór alle andere stappen.
   a. `git fetch origin` en `git branch -r` — bekijk ALLE branches, niet alleen main.
   b. Bepaal per branch of hij commits bevat die jij nog niet hebt:
      `git rev-list --count HEAD..origin/<andere>`. Is dat 0, dan kun je hem negeren.
      LET OP: de container levert de repo vaak als ONDIEPE kloon aan. Draai dan eerst
      `git fetch --unshallow origin`, anders tellen alle commits van vóór de knip mee als
      "nog niet hier" en zie je tientallen takken die in werkelijkheid allang binnen zijn.
   c. Bevat een andere branch wél eigen commits, merge hem dan. Kies niet tussen takken en
      gooi er geen weg: op 10 aug 2026 hadden beide takken werk dat de ander niet had. Bij
      conflicten in data/picks.jsonl, data/source-health.json en data/coverage.json is de
      VERENIGING het antwoord — beide runs hebben echt gemeten, en een pick die op één tak
      staat is een echte pick. Bij _shared-rules.md en de scripts wint de nieuwste versie.
   d. Controleer daarna of picks.jsonl openstaande picks bevat van een run die op de andere
      tak nooit is afgewikkeld. Die horen bij Stage 0 — ook picks van Run A en Run B.
   e. Kom je om wat voor reden dan ook niet op main uit, meld dat dan bovenaan het runrapport
      én in de notificatie.
