WAAROM DEZE AFSTANDEN, MET DE GEMETEN LOOPTIJDEN ERBIJ. Elke run legt sinds 5 sep 2026 zijn

  Run A   mediaan 31,5 min   langste normale run 41,7 min   (twee keer een incident van ~11 uur)
  Run B   mediaan 29,4 min   langste 91,0 min
  Run C   mediaan  0,3 min   maar 17 tot 43 min op een dag MET interlands (eenmalig 177 min)

A om 02:47 is om ongeveer 03:20 klaar, dus B om 03:47 valt hem niet in de rede. C staat om 05:17
na een normale B (die rond 04:20 klaar is) en heeft dan ruim een uur tot de deadline — genoeg
voor de 17 tot 43 minuten die een interlanddag kost. Liep B uit tot 91 minuten, zoals op
1 nov 2026, dan start C tóch nog tijdens B; dat kost een merge en geen data (stap 0 en §6a
handelen het af: fetch, merge, push nog een keer, nooit forceren).

Wil je die laatste overlap helemaal weg, dan is C vóór A zetten de robuustere oplossing — 02:17,
met A om 02:47 — want C duurt op negen van de tien dagen minder dan een minuut en A's staart is
korter en voorspelbaarder dan die van B. De keerzijde is dat C dan op een interlanddag A kan
ophouden. Dat is een afweging voor de gebruiker; 05:17 is wat hij op 2 nov 2026 heeft gekozen.

0. EERST DE BRANCHES OP ORDE. Doe dit vóór alle andere stappen.
   a. `git fetch origin` en `git branch -r` — bekijk ALLE branches, niet alleen main.
   b. Bepaal per branch of hij commits bevat die jij nog niet hebt:
      `git rev-list --count HEAD..origin/<andere>`. Is dat 0, dan kun je hem negeren.
      LET OP: de container levert de repo vaak als ONDIEPE kloon aan. Draai dan eerst
      `git fetch --unshallow origin`, anders tellen alle commits van vóór de knip mee als
      "nog niet hier" en zie je tientallen takken die in werkelijkheid allang binnen zijn.
   c. Bevat een andere branch wél eigen commits, merge hem dan. Kies niet tussen takken en
      gooi er geen weg: op 10 aug 2026 hadden beide takken werk dat de ander niet had. Bij

      VERENIGING het antwoord — beide runs hebben echt gemeten, en een pick die op één tak
      staat is een echte pick. Bij _shared-rules.md en de scripts wint de nieuwste versie.
   d. Controleer daarna of picks.jsonl openstaande picks bevat van een run die op de andere

      én in de notificatie.
