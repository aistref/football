## De bron die twee antwoorden geeft

Dit is de enige echte bevinding van vandaag, en ze is per ongeluk gevonden: de eerste
BetExplorer-ronde gaf voor de Czech First League 8 rijen en de tweede, twee minuten later, 0. Zelfde

|---|---|---|---|---|---|---|

| omvang van de pagina (bytes) | 201.868 | 195.941 | 201.868 | 195.941 | 195.941 | 201.868 |

**BetExplorer serveert twee versies van dezelfde pagina** — één mét `data-odd` en één zonder, met
verder identieke inhoud (169 teamparen, 63 datumlabels, in beide). `romania/superliga` doet
hetzelfde (24/24/0/0/24/0). Vijf andere competities gaven bij zes verzoeken een constant antwoord,
dus het treft niet alles.

**Waarom dit meer is dan een curiositeit.** `fetch_league_fixtures` eist ten minste drie koersen per
rij, dus op de versie zonder `data-odd` geeft hij **nul rijen** — en nul rijen leest in een
runrapport als "geen wedstrijden vandaag". Dat is precies de stille faalmodus waar `betexplorer.py`
in zijn eigen commentaar drie keer voor waarschuwt, alleen nu niet door een verkeerde slug maar door
de bron zelf, en dus niet te herkennen aan een vaste slug-lijst. Op een dag met een volle speelronde
had één ongelukkig verzoek een hele competitie onzichtbaar gemaakt, met nul rijen als bewijs.

Het verklaart bovendien iets in het rapport van gisteren. Run B noteerde toen vijf competities met
"0 rijen met prijs" en legde dat uit als *er is nog geen koers genoteerd*. Voor Croatian HNL en
Hungarian NB I klopt dat, en vandaag nog steeds. Voor Allsvenskan, Swiss Super League en
2. Bundesliga niet: die geven vandaag gewoon 8, 6 en 9 rijen, en gaven bij zes verzoeken een constant
antwoord. Minstens een deel van die vijf was dus deze variant en niet het ontbreken van prijzen.

**Wat eraan gedaan is.** `fetch_league_fixtures` herhaalt het verzoek voortaan (maximaal drie keer,
1,5 seconde ertussen) zodra de pagina wél teamparen maar géén koersen geeft. Nul teamparen blijft
een verkeerde slug en daar helpt herhalen niet, dus dat geval wordt niet nodeloos vertraagd.
Gecontroleerd na de wijziging, vijf verzoeken per competitie:

| Competitie | Vóór | Ná |
|---|---|---|
| Czech First League | 0 / 8 / 0 / 8 / 0 wisselend | 8 / 8 / 8 / 8 / 8 |
| Romanian SuperLiga | 8 / 0 / 8 wisselend | 8 / 8 / 8 / 8 / 8 |
| Croatian HNL | 0 | 0 / 0 / 0 / 0 / 0 (terecht — geen prijzen) |
| Hungarian NB I | 0 | 0 / 0 / 0 / 0 / 0 (terecht — geen prijzen) |

Lees "0 rijen" vanaf nu dus in drie smaken, en schrijf in het runrapport op welke het is:

1. **nul teamparen** → verkeerde slug;
2. **teamparen zonder koers, ook ná herhaling** → de ronde heeft nog geen prijzen;
3. **teamparen mét koers ná herhaling** → dit was de wisselende variant.

Dat onderscheid staat nu ook in `data/source-health.json` en in `data/coverage.json`.
